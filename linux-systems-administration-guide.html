1. The Linux Filesystem Hierarchy Standard (FHS)

Unlike Windows which organizes storage around drive letters (C:\, D:\), the Linux operating system adheres to the unified Filesystem Hierarchy Standard (FHS). Every physical device, virtual subsystem, configuration file, and user profile exists as a node descending from the single root directory represented by a forward slash (/).

/
/bin

Essential user command binaries (e.g., ls, cp, cat) required in single-user mode and recovery boot.

/boot

Static bootloader files, Linux kernel image (vmlinuz), and Initial RAM Disk (initramfs).

/dev

Device nodes representing physical hardware, disks (sda, nvme0n1), terminals, and pseudodevices (/dev/null).

/etc

Host-specific, system-wide configuration files (e.g., nginx.conf, fstab, passwd). No executable binaries.

/home

User personal home directories containing documents, personal settings, and user-level configs (/home/tasim).

/lib & /lib64

Shared library modules (.so files) essential for binaries in /bin and /sbin, plus kernel drivers.

/media & /mnt

Mount points: /media for automatic removable media (USB, CD-ROM); /mnt for temporary manual mounts.

/opt

Add-on application software packages from third-party vendors structured as self-contained directories.

/proc

Virtual pseudo-filesystem providing a real-time window into kernel data structures, PID metrics, and hardware state.

/root

The dedicated home directory for the superuser (root). Separate from standard user directories in /home.

/run

Runtime variable data (e.g., active daemon PIDs, Unix sockets) stored in a temporary filesystem (tmpfs) since boot.

/sbin

System administrator management binaries (e.g., iptables, fdisk, reboot, ip) requiring root privileges.

/srv

Site-specific data served directly by the server instance (e.g., FTP storage pools, web repositories).

/sys

Virtual sysfs filesystem exposing the kernel device tree, driver buses, power states, and hardware tunables.

/tmp

Temporary volatile scratchpad storage accessible to all processes; flushed automatically across reboots.

/usr

Unix System Resources: secondary hierarchy containing non-critical read-only user utilities, libraries, and share data.

/var

Variable data expected to continuously expand during system operation (system logs /var/log, spool, web roots /var/www).

2. Filesystem Hierarchy & Inode Metadata Search: find

While grep reads file data streams, find traverses the directory tree inspecting inode metadata (timestamps, ownership, size, permissions, and file types): 

# 1. Search by Name and File Type
find /etc -iname "*nginx*"                 # Case-insensitive filename lookup
find /var/www -type d                      # Find all directories only
find /var/www -type f                      # Find all regular files only
find /var/run -type s                      # Find active UNIX domain sockets

# 2. Search by Size (Finding Disk Space Consumers)
find /var/log -type f -size +100M          # Files larger than 100MB
find /var/log -type f -size +1G            # Massive logs consuming volume space
find /tmp -type f -empty                   # Zero-byte garbage files

# 3. Search by Temporal Inode Timestamps (Modification, Access, Inode Change)
find /var/log -mtime -1                    # Modified within the last 24 hours
find /var/log -name "*.log" -mtime +30     # Modified more than 30 days ago
find /tmp -mmin -60                        # Modified in the last 60 minutes
find /home -atime +90                      # Not accessed for more than 90 days

# 4. Critical Security Audits: SUID & World-Writable Files
find / -perm -4000 -type f 2>/dev/null     # Discover all SUID root binaries (privilege escalation check)
find /var/www -perm 777 -type f            # Unsafe world-writable files in web root
find / -nouser -o -nogroup 2>/dev/null     # Orphaned files without valid owner

# 5. Pipeline Actions with -exec and xargs
find /var/log -name "*.log" -mtime +30 -exec gzip {} \;      # Compress old logs in place
find /var/www/html -type d -exec chmod 755 {} +             # Batch enforce directory permissions
find /var/www/html -type f -exec chmod 644 {} +             # Batch enforce file permissions
find . -type f -name "*.tmp" -print0 | xargs -0 rm -f       # Safe null-byte deletion for files with spaces

3. High-Speed Index Search: locate & updatedb

Real-Time Traversal vs Indexed Binary Search

find traverses the physical storage volume in real-time, which is thorough but can trigger heavy I/O latency on multi-terabyte arrays. locate queries a pre-indexed binary database (/var/lib/mlocate/mlocate.db) returning results in milliseconds. The database is indexed daily by cron or manually refreshed via sudo updatedb. 

# Fast Indexed Search Workflows
sudo updatedb                      # Re-index filesystem inodes into mlocate database
locate nginx.conf                  # Instant lookup of all paths matching 'nginx.conf'
locate -i "settings.py"            # Case-insensitive indexed query
locate -c "*.png"                  # Instant count of all PNG images on the host

6. Reverse Shell History Searching

When working in production bash terminals, searching previously executed commands avoids syntax errors:

  • Ctrl + R: Reverse Incremental History Search. Type any keyword (e.g., docker or systemctl) to instantly recall the most recent matching command. Press Ctrl + R repeatedly to cycle backward through history.
  • history | grep "systemctl": Search entire session history buffer.
  • !grep: Re-execute the most recent command that began with grep.
  • !!: Re-execute the previous command (commonly used as sudo !!).

4. Linux Security Architecture: Permissions & Octal Mathematics

Linux enforces a strict Discretionary Access Control (DAC) model where every file and directory is bound to an Owner, a Primary Group, and Others. This is represented by a 10-character mode string in ls -l.

FILE DESCRIPTOR MODE ANATOMY
- r w x r - x r - -
Bit 1: File Type
- (Regular)
- file, d dir, l link, b block, c char, s sock
Bits 2-4: Owner (u)
r w x (7)
Read (4) + Write (2) + Exec (1) = Full ownership permissions
Bits 5-7: Group (g)
r - x (5)
Read (4) + Execute (1) = Group members can read & execute
Bits 8-10: Other (o)
r - - (4)
Read (4) only = World can read but cannot write or execute
# Symbolic Permission Modifications
chmod u+r file.txt      # Grant read permission to Owner (User)
chmod g-w file.txt      # Revoke write permission from Group
chmod o+x script.sh     # Grant execute permission to Others (World)
chmod a+r document.pdf  # Grant read permission to All (u, g, and o)

# Octal Permission Calculations: 754 -> (4+2+1=7 User) (4+0+1=5 Group) (4+0+0=4 Other)
chmod 754 script.sh
chmod -R 755 /var/www/html    # Recursively enforce 755 across web assets
chmod 600 ~/.ssh/id_rsa       # Strict privacy: only owner can read/write private key

# Ownership & User Administration
chown tasim:tasim report.log           # Change user and group ownership
chown -R www-data:www-data /var/www    # Enforce web server ownership
chgrp devops deployment.sh             # Change group ownership only
sudo useradd -m -s /bin/bash devops    # Create new user with home directory and shell
sudo passwd devops                     # Set user password
su - devops                            # Switch to devops shell environment with full environment load

5. Kernel Process Lifecycle, Niceness & Signal Handling

Every task executed in Linux is assigned a unique Process Identifier (PID). The Linux kernel schedules threads dynamically across physical CPU cores using the Completely Fair Scheduler (CFS).

RUNNING (R)

Active Execution

Process is either actively consuming CPU cycles or waiting in the run queue for scheduler time-slice.

INTERRUPTIBLE (S)

Sleeping on Event

Waiting for a specific event, socket packet, timer, or I/O availability. Wakes up immediately upon receiving signals.

STOPPED (T)

Job Suspended

Halted via job control signal (e.g., Ctrl+Z / SIGTSTP) or under active tracing by a debugger (ptrace).

ZOMBIE (Z)

Defunct Child

Process has terminated execution, but its exit status has not yet been reaped by its parent via wait().

# Background Execution and Job Management
python3 worker.py &    # Launch process directly into background
jobs -l                # List background job IDs with their PIDs
Ctrl + Z               # Send SIGTSTP: suspend active foreground job
bg %1                  # Resume job 1 in the background
fg %1                  # Bring job 1 back to the active foreground

# Process Signals
kill -15 <PID>         # SIGTERM: Graceful termination request (allows cleanup)
kill -9  <PID>         # SIGKILL: Immediate kernel-level destruction (cannot be caught or ignored)
kill -1  <PID>         # SIGHUP: Hangup signal; forces daemons (Nginx/Postgres) to reload configuration
killall -9 nginx       # Terminate all running processes matching the name 'nginx'
pkill -u www-data      # Terminate all processes owned by the 'www-data' user

# Niceness & CPU Scheduling Priority (-20 to 19 scale)
nice -n -10 ./database_indexer   # Launch with elevated priority (requires sudo)
renice +5 -p 1842                # Demote priority of existing process with PID 1842

7. Systemd (System D) Architecture & Daemon Engineering (systemctl, journalctl, timers, cgroups)

Systemd (abbreviated System D for System Daemon) is the modern init system and service manager across all mainstream enterprise Linux distributions (Ubuntu, Debian, RHEL, CentOS, Rocky Linux, Amazon Linux 2 & AL2023). Initialized by the Linux kernel as PID 1, System D orchestrates parallelized boot sequences, socket activation, dependency trees, filesystem mounts, hardware events, and cgroup resource isolation.

System D (PID 1) Boot Hierarchy & Daemon Architecture

1. System D Targets vs Legacy SysVinit Runlevels

In legacy Unix systems (SysVinit), states were defined by numerical runlevels (0 through 6). System D replaces runlevels with Target Units (.target), which act as synchronization checkpoints:

Legacy Runlevel System D Target Unit Operational Purpose Isolation Command
Runlevel 0 poweroff.target Halts hardware and shuts down power. sudo systemctl isolate poweroff.target
Runlevel 1 / S rescue.target Single-user administrative maintenance mode. sudo systemctl isolate rescue.target
Runlevel 3 multi-user.target Standard non-graphical multi-user server environment. sudo systemctl set-default multi-user.target
Runlevel 5 graphical.target Multi-user environment with X11 / Wayland display manager. sudo systemctl isolate graphical.target
Runlevel 6 reboot.target Clean shutdown and hardware reboot. sudo systemctl isolate reboot.target
Emergency emergency.target Minimal shell with read-only root for fsck repairs. sudo systemctl isolate emergency.target

2. System D Service Lifecycle States

INACTIVE

Unit Stopped

Daemon unloaded. Zero PIDs allocated in memory.

ACTIVATING

Startup Sequence

ExecStartPre and environment loading in progress.

ACTIVE

Running Steady

Process listening on sockets and handling incoming traffic.

RELOADING

Graceful Reload

ExecReload dispatched (SIGHUP) refreshing configs without connection drop.

FAILED

Crashed / Dead

Terminated with non-zero exit code or timeout failure.

3. Mastering systemctl Service Control

# 1. Daemon Runtime Control
sudo systemctl start nginx.service          # Immediately start daemon
sudo systemctl stop nginx.service           # Graceful shutdown (SIGTERM)
sudo systemctl restart nginx.service        # Full restart (Stop -> Start fresh)
sudo systemctl reload nginx.service         # SIGHUP configuration reload without dropping TCP sockets
sudo systemctl status nginx.service         # Inspect health, active PID, memory cgroup, and recent log tail

# 2. Boot Persistence (Symlinking into /etc/systemd/system/multi-user.target.wants/)
sudo systemctl enable nginx                 # Enable service to boot automatically
sudo systemctl disable nginx                # Prevent service from booting automatically
sudo systemctl enable --now mariadb         # Enable persistence AND start immediately in one command

# 3. Security Unit Masking & Unmasking (Preventing Accidental Starts)
sudo systemctl mask apache2                 # Symlinks unit to /dev/null; CANNOT be started by user or dependency!
sudo systemctl unmask apache2               # Restore unit file access

# 4. Service Auditing, Introspection & Failure Triage
systemctl is-active nginx                   # Returns 'active' or 'inactive' (exit code 0/3 for shell scripts)
systemctl is-enabled nginx                  # Returns 'enabled' or 'disabled'
systemctl is-failed nginx                   # Returns 0 if failed, non-zero if healthy
systemctl --failed                          # Instant audit of ALL currently broken or crashed units across host!
systemctl reset-failed                      # Clear failed state markers after rectifying root cause

# 5. Unit Inspection & Drop-In Configuration Overrides
systemctl cat nginx.service                 # Print raw unit definition from disk
sudo systemctl edit nginx.service           # Creates drop-in override: /etc/systemd/system/nginx.service.d/override.conf
sudo systemctl edit --full nginx.service    # Copies entire unit into /etc/systemd/system/ for full customization
systemctl list-dependencies nginx.service   # Print ASCII tree of required unit dependencies

# 6. Configuration Reload & System State
sudo systemctl daemon-reload                # Reread all modified unit files from disk without rebooting!
sudo systemctl reboot                       # Orderly system reboot
sudo systemctl poweroff                     # Orderly ACPI power down

[Install]
WantedBy=multi-user.target

5. System D Timers (.timer) - The Modern Replacement for Cron

System D Timers supersede legacy crontab by offering nanosecond accuracy, automatic logging via journald, dependency resolution, and monotonic scheduling (e.g. 15 minutes after system boot). 

# Step 1: Create the matching Service: /etc/systemd/system/db-backup.service
[Unit]
Description=Automated PostgreSQL Production Backup

[Service]
Type=oneshot
User=postgres
ExecStart=/usr/local/bin/pg_backup.sh

# Step 2: Create the Timer Unit: /etc/systemd/system/db-backup.timer
[Unit]
Description=Trigger PostgreSQL Backup Daily at 02:30 AM
Requires=db-backup.service

[Timer]
OnCalendar=*-*-* 02:30:00
Persistent=true
RandomizedDelaySec=300

[Install]
WantedBy=timers.target
# Managing and Auditing System D Timers
sudo systemctl daemon-reload
sudo systemctl enable --now db-backup.timer
systemctl list-timers --all                 # Inspect next scheduled trigger, time left, and last execution!

8. Advanced Log Streaming & Incident Triage: journalctl

journalctl queries the binary log database compiled by systemd-journald. Unlike plain text logs in /var/log, journald logs include indexed metadata (UID, PID, service unit, kernel boot ID): 

# 1. Live Streaming Logs (Replacing tail -f)
journalctl -u nginx.service -f              # Follow active service logs in real time
journalctl -u api-backend.service -f -n 50  # Follow with 50 lines of preceding context

# 2. Post-Mortem Crash Autopsy
journalctl -xe                              # Jump to end of log with error explanations (-e) and extra catalog data (-x)
journalctl -k                               # Print Linux Kernel ring buffer logs (hardware faults, OOM events)

# 3. Boot-Scoped Incident Analysis
journalctl --list-boots                     # Display list of all recorded host boots and timestamps
journalctl -b 0                             # Inspect logs recorded during current boot only
journalctl -b -1                            # Inspect logs recorded during the PREVIOUS boot (essential after an unexpected kernel panic!)

# 4. Strict Time-Window Filtering
journalctl --since "1 hour ago"             # Logs from the last 60 minutes
journalctl --since "2026-10-18 09:00:00" --until "2026-10-18 10:30:00"

# 5. Filtering by Priority Severity
journalctl -p err..emerg                    # Filter log severity: Errors (3), Critical (2), Alerts (1), Emergencies (0)

# 6. Disk Maintenance & Space Vacuuming
journalctl --disk-usage                     # Check total disk size consumed by journal files
sudo journalctl --vacuum-time=14d           # Purge log archives older than 14 days
sudo journalctl --vacuum-size=500M          # Cap journal storage footprint to 500 Megabytes

9. Terminal Mastery: Vim Modal Architecture, Nano & Bash Shortcuts

Mastering CLI text editors and readline shortcuts separates novice users from senior infrastructure architects.

NORMAL MODE

The default hub. Commands navigate, delete, copy, and manipulate text.

h/j/k/l (move) dd (delete line) yy (yank line) p (paste) u (undo) Ctrl+R (redo) /pattern (search) gg (top) G (bottom)
INSERT MODE

Direct text typing into buffer. Enter via specific trigger keys; exit with Esc.

i (insert at cursor) a (append after) o (open line below) O (open line above) I (insert at start) A (append at end) Esc (return to Normal)
COMMAND-LINE MODE

Execute ex-commands, search/replace regex, save buffers, or quit.

:w (write/save) :q (quit) :wq! (save & force quit) :q! (discard changes) :%s/old/new/g (replace) :set number (line nos)
