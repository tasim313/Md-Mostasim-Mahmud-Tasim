1. The Linux Filesystem Hierarchy Standard (FHS)

Unlike Windows which organizes storage around drive letters (C:\, D:\), the Linux operating system adheres to the unified Filesystem Hierarchy Standard (FHS). Every physical device, virtual subsystem, configuration file, and user profile exists as a node descending from the single root directory represented by a forward slash (/).

/
/bin

Essential user command binaries (e.g., ls, cp, cat) required in single-user mode and recovery boot.

/boot

Static bootloader files, Linux kernel image (vmlinuz), and Initial RAM Disk (initramfs).

/dev

Device nodes representing physical hardware, disks (sda, nvme0n1), terminals, and pseudodevices (/dev/null).

/etc

Host-specific, system-wide configuration files (e.g., nginx.conf, fstab, passwd). No executable binaries.

/home

User personal home directories containing documents, personal settings, and user-level configs (/home/tasim).

/lib & /lib64

Shared library modules (.so files) essential for binaries in /bin and /sbin, plus kernel drivers.

/media & /mnt

Mount points: /media for automatic removable media (USB, CD-ROM); /mnt for temporary manual mounts.

/opt

Add-on application software packages from third-party vendors structured as self-contained directories.

/proc

Virtual pseudo-filesystem providing a real-time window into kernel data structures, PID metrics, and hardware state.

/root

The dedicated home directory for the superuser (root). Separate from standard user directories in /home.

/run

Runtime variable data (e.g., active daemon PIDs, Unix sockets) stored in a temporary filesystem (tmpfs) since boot.

/sbin

System administrator management binaries (e.g., iptables, fdisk, reboot, ip) requiring root privileges.

/srv

Site-specific data served directly by the server instance (e.g., FTP storage pools, web repositories).

/sys

Virtual sysfs filesystem exposing the kernel device tree, driver buses, power states, and hardware tunables.

/tmp

Temporary volatile scratchpad storage accessible to all processes; flushed automatically across reboots.

/usr

Unix System Resources: secondary hierarchy containing non-critical read-only user utilities, libraries, and share data.

/var

Variable data expected to continuously expand during system operation (system logs /var/log, spool, web roots /var/www).

Directory Traversal and Inspection Operators

The cd and ls commands form the bedrock of shell navigation: 

# Absolute Navigation
cd /usr/local/lib
pwd   # Output: /usr/local/lib

# Relative Navigation
cd ../..   # Traverse 2 directory levels upward
cd -       # Toggle back to the PREVIOUS working directory (acts like browser back)
cd ~       # Return to user's home directory ($HOME)

# Advanced Directory Listing Flags
ls -l      # Long listing format (permissions, links, owner, group, size, mtime)
ls -a      # Include hidden files (dotfiles: .bashrc, .profile)
ls -lh     # Long listing with human-readable binary file sizes (K, M, G)
ls -lt     # Sort entries chronologically by modification timestamp (newest first)
ls -ltr    # Reverse chronological sort (most recently touched file appears at the bottom)
ls -i      # Display unique filesystem inode numbers for each entry
ls -R      # Recursively traverse and list entire subtree hierarchies
The Engineering Distinction Between 'ls' and 'ls -a'

In Unix systems, files beginning with a dot (.) are intentionally hidden from everyday shell visibility to prevent cluttering application directories. However, in production troubleshooting, over 90% of security breaches and misconfigurations lurk inside dotfiles (e.g., .ssh/authorized_keys, .env, .bash_history). Running ls -al is mandatory during server audits.

3. Linux Security Architecture: Permissions & Octal Mathematics

Linux enforces a strict Discretionary Access Control (DAC) model where every file and directory is bound to an Owner, a Primary Group, and Others. This is represented by a 10-character mode string in ls -l.

FILE DESCRIPTOR MODE ANATOMY
- r w x r - x r - -
Bit 1: File Type
- (Regular)
- file, d dir, l link, b block, c char, s sock
Bits 2-4: Owner (u)
r w x (7)
Read (4) + Write (2) + Exec (1) = Full ownership permissions
Bits 5-7: Group (g)
r - x (5)
Read (4) + Execute (1) = Group members can read & execute
Bits 8-10: Other (o)
r - - (4)
Read (4) only = World can read but cannot write or execute

Octal Weight Formula & chmod Execution

Permission Bit Symbolic Octal Value Binary Weight Meaning on Files Meaning on Directories
Read r 4 100 View file contents (cat, less) List directory contents (ls)
Write w 2 010 Modify file contents Create, rename, or delete files inside directory
Execute x 1 001 Run file as a program or script Enter directory (cd) and access its inodes 
# Symbolic Permission Modifications
chmod u+r file.txt      # Grant read permission to Owner (User)
chmod g-w file.txt      # Revoke write permission from Group
chmod o+x script.sh     # Grant execute permission to Others (World)
chmod a+r document.pdf  # Grant read permission to All (u, g, and o)

# Octal Permission Calculations
# Example: 754 -> (4+2+1=7 User) (4+0+1=5 Group) (4+0+0=4 Other)
chmod 754 script.sh
chmod -R 755 /var/www/html    # Recursively enforce 755 across web assets
chmod 600 ~/.ssh/id_rsa       # Strict privacy: only owner can read/write private key

# Ownership & User Administration
chown tasim:tasim report.log           # Change user and group ownership
chown root:root /etc/nginx/nginx.conf  # Enforce root governance
sudo useradd -m -s /bin/bash devops    # Create new user with home directory and shell
sudo passwd devops                     # Set user password
su - devops                            # Switch to devops shell environment with full environment load

4. Kernel Process Lifecycle, Niceness & Signal Handling

Every task executed in Linux is assigned a unique Process Identifier (PID). The Linux kernel schedules threads dynamically across physical CPU cores using the Completely Fair Scheduler (CFS).

RUNNING (R)

Active Execution

Process is either actively consuming CPU cycles or waiting in the run queue for scheduler time-slice.

INTERRUPTIBLE (S)

Sleeping on Event

Waiting for a specific event, socket packet, timer, or I/O availability. Wakes up immediately upon receiving signals.

STOPPED (T)

Job Suspended

Halted via job control signal (e.g., Ctrl+Z / SIGTSTP) or under active tracing by a debugger (ptrace).

ZOMBIE (Z)

Defunct Child

Process has terminated execution, but its exit status has not yet been reaped by its parent via wait().

Job Control & Shell Signal Dispatching

# Background Execution and Job Management
python3 worker.py &    # Launch process directly into background
jobs -l                # List background job IDs with their PIDs
Ctrl + Z               # Send SIGTSTP: suspend active foreground job
bg %1                  # Resume job 1 in the background
fg %1                  # Bring job 1 back to the active foreground

# Process Signals
kill -15 <PID>         # SIGTERM: Graceful termination request (allows cleanup)
kill -9  <PID>         # SIGKILL: Immediate kernel-level destruction (cannot be caught or ignored)
kill -1  <PID>         # SIGHUP: Hangup signal; forces daemons (Nginx/Postgres) to reload configuration
killall -9 nginx       # Terminate all running processes matching the name 'nginx'
pkill -u www-data      # Terminate all processes owned by the 'www-data' user

# Niceness & CPU Scheduling Priority (-20 to 19 scale)
# -20 = Highest Priority (more aggressive CPU time slices)
#  19 = Lowest Priority (idle/polite background processing)
nice -n -10 ./database_indexer   # Launch with elevated priority (requires sudo)
renice +5 -p 1842                # Demote priority of existing process with PID 1842

1 root 20 0 168836 13232 7472 S 0.0 0.2 0:04.41 systemd

Header Telemetry Deep Dive

  • Load Average (2.08, 3.70, 3.37): Represents the average number of computational threads in a runnable (CPU) or uninterruptible disk I/O state over 1, 5, and 15 minutes. On a 4-core CPU, any load under 4.0 indicates headroom. A load of 8.0 indicates a 100% backlog waiting for compute.
  • %Cpu(s) Metrics:
    • us (User Time): Percentage of CPU cycles executing un-niced user space processes (e.g., Python, Nginx, Node.js).
    • sy (System Time): Percentage of CPU time spent executing kernel routines and handling system calls.
    • wa (I/O Wait): Critical Performance Indicator. Measures CPU idle time spent blocked on slow disk storage or remote NFS latency. Values above 10% indicate an I/O bottleneck.
    • st (Steal Time): In cloud environments (AWS EC2 / GCP), indicates CPU cycles stolen by the hypervisor to service other noisy virtual machines.
  • Memory (VIRT vs RES vs SHR):
    • VIRT: Virtual memory reserved by the process (including mapped files and unallocated heap).
    • RES: Resident Memory — the exact amount of physical, non-swapped RAM currently occupied by the process.
    • SHR: Shared memory segments accessible to other libraries and child processes.

Interactive Control Commands

P Key

Sort process table by %CPU utilization (default sort order).

M Key

Sort process table by %MEM (RAM consumption).

N Key

Sort process table alphabetically by command name.

T Key

Sort process table by cumulative execution CPU time (TIME+).

k Key

Prompt for a PID to send a signal directly without exiting top.

r Key

Renice an active process interactively to alter its scheduling.

d Key

Change refresh rate interval (e.g., 5 seconds to reduce top load).

W Key

Write current customized view preferences to ~/.toprc.

6. Storage Diagnostics & Archive Compression Pipelines

System stability requires proactive storage auditing and efficient asset bundling. 

# Disk Space & Storage Inspection
df -h               # Filesystem disk consumption in human-readable gigabytes
du -sh /var/log     # Cumulative disk consumption of a specific folder
du -h --max-depth=1 /home | sort -hr  # Identify largest storage-hogging home folders
lsblk               # Print hierarchical tree of block storage devices and partitions
free -m             # Instant RAM and Swap utilization in Megabytes
cat /proc/meminfo   # Detailed breakdown of kernel memory buffers and dirty pages

The Tarball Archiving & Compression Pipeline

The tar (Tape Archive) utility aggregates thousands of individual files into a single contiguous stream. It does not compress data by itself; rather, it passes the resulting stream through compression engines such as gzip (balanced speed/compression) or bzip2 (maximum ratio).

Archival & Compression Flow

Input Source Files
(Directory Tree)
→
tar -cf
(Archive Container)
→
gzip (-z) / bzip2 (-j)
(Compression Engine)
→
archive.tar.gz
(Production Asset)
# Creation Commands
tar -cf archive.tar /data/files            # Create uncompressed tar archive
tar -czf site_backup.tar.gz /var/www/html # Create tar archive with GZIP compression (.tar.gz)
tar -cjf db_dump.tar.bz2 /var/lib/mysql   # Create tar archive with BZIP2 compression (.tar.bz2)
zip -r backup.zip /var/www/html           # Create standard ZIP file

# Extraction Commands
tar -xf archive.tar                       # Extract standard tar archive
tar -xzf site_backup.tar.gz -C /opt       # Extract GZIP tarball directly into /opt
tar -xjf db_dump.tar.bz2                  # Extract BZIP2 tarball
unzip backup.zip -d /extracted            # Extract ZIP file into target folder
gzip -d file.gz                           # Decompress standalone gzip file back to original

7. Network Probing & Secure SCP Remote Workflows

Production system engineers frequently manage fleet servers remotely over encrypted transport layers. 

# Network Connectivity Diagnostics
ping -c 4 8.8.8.8       # Transmit 4 ICMP echo packets to test latency and packet loss
ip addr show            # Display network interfaces, IP leases, and MAC addresses (modern ifconfig)
netstat -tulnp          # List all active TCP/UDP listening ports with PID association (or ss -tulnp)
dig example.com +short  # DNS forward resolution (A records)
dig -x 93.184.216.34    # Reverse DNS lookup (PTR record)
whois example.com       # Domain registration and registrar details
wget -c https://example.com/asset.iso  # Download asset with automatic resume support

Secure Remote Copying (SCP) Pipeline

The scp utility establishes an encrypted SSH tunnel to stream files bidirectionally using cryptographic key pairs:

Bidirectional SCP Data Transfer Flow

Local Workstation
(./desktop/image.jpg)
→
SSH Protocol (Port 22)
Key Auth: -i id_rsa.pem
→
Remote Cloud Server
(ubuntu@IP:/var/www/uploads/)
# 1. Local Workstation -> Remote Server Upload
scp -i ~/.ssh/cloud_key.pem ./build.tar.gz ubuntu@54.210.12.33:/var/www/

# 2. Remote Server -> Local Workstation Download
scp -i ~/.ssh/cloud_key.pem ubuntu@54.210.12.33:/var/log/nginx/error.log ./local_logs/

# 3. Recursive Directory Transfer
scp -r -i ~/.ssh/cloud_key.pem ./assets ec2-user@54.210.12.33:/home/ec2-user/site/

8. Enterprise Web Stack Orchestration (Nginx, Apache, PHP-FPM, MariaDB)

A complete systems administration runbook comparing Ubuntu (Debian ecosystem) against Amazon Linux 2 / AL2023 (RHEL ecosystem).

Web Gateway

Nginx Engine

  • Ubuntu: apt install nginx
  • Amazon Linux 2: amazon-linux-extras install nginx1
  • AL2023: dnf install nginx -y
  • Root: /usr/share/nginx/html
Application Server

Apache HTTPD

  • Ubuntu: apt install apache2
  • Amazon Linux: yum install httpd -y
  • Service: systemctl start httpd
  • Root: /var/www/html
Runtime Backend

PHP-FPM 8.1

  • AL2: amazon-linux-extras install php8.1

Relational Storage

MariaDB / MySQL

  • Security: mariadb-secure-installation
  • Autostart: systemctl enable mariadb
